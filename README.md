# Фильтр SMS-спама

## Задача

Учебный классификатор оценивает вероятность спама и применяет порог с приоритетом высокой
precision: ошибочная блокировка обычного сообщения считается особенно нежелательной.
Модель должна быть частью многоуровневой защиты, а не единственным основанием блокировки.

## Структура каталогов

- `src/sms_spam_filter/` — загрузка, TF-IDF pipelines, порог и train/evaluate/predict CLI;
- `tests/` — проверки дедупликации, порога, артефакта и полного smoke-pipeline;
- `data/README.md` — источник и формат корпуса; `notebooks/` — исполненный smoke-эксперимент;
- `artifacts/` — локальная модель, метрики и test predictions.

## Используемые технологии

Python 3.11, NumPy, pandas, scikit-learn и joblib; pytest и Ruff для QA.

## Требования к окружению

Python `>=3.11,<3.12` и `pip`; Makefile использует `python3.11`. Установка: `make install`.

## Данные

Целевой источник — [UCI SMS Spam Collection](https://archive.ics.uci.edu/dataset/228/sms+spam+collection),
лицензия CC BY 4.0. Поддерживаются официальный tab-separated файл (`ham`/`spam`) и CSV с
`label,text`. Набор не скачивается автоматически. `make smoke` создаёт синтетические
сообщения с фиксированным алгоритмом.

## Ограничения данных

Корпус собран из нескольких англоязычных источников и не отражает современный поток,
русский язык, sender metadata и новые кампании. Сообщения могут содержать персональные
фрагменты; реальный файл не коммитится. Smoke-метрики не являются реальными метриками.

## Методология и защита от утечек

Текст приводится к casefold и нормализованным пробелам для fingerprint. Конфликтующие
метки одного fingerprint запрещены, дубликаты удаляются до стратифицированного split
`60/20/20`. TF-IDF обучается только на train. На validation выбираются представление и
порог, test используется один раз для итогового отчёта. Перед оценкой проверяются версия
model bundle, семантика классов, допустимость порога и интерфейс `predict_proba`.

## Baseline и эксперименты

| Эксперимент | Признаки | Выбор |
| --- | --- | --- |
| keyword rule | `free`, `win`, `claim`, `urgent` | наивный baseline |
| word TF-IDF | word 1–2 grams | validation PR-AUC |
| char TF-IDF | char 3–5 grams | validation PR-AUC |
| combined TF-IDF | объединение word + char | validation PR-AUC |

## Порог и итоговая метрика

Для каждой модели на validation ищется порог, достигающий заданной precision. Среди моделей,
выполнивших ограничение, выбирается вариант с максимальным recall, затем PR-AUC. Если ни
одна модель не выполнила ограничение, это явно записывается, а fallback максимизирует
precision без пустого множества предсказаний. До запуска на зафиксированном UCI-файле лучшая
модель и числа не объявлены; отчёт находится в `artifacts/metrics.json`.

## Устойчивость и короткие сообщения

Test-отчёт отдельно считает метрики для текстов короче 40 символов и долю обнаружения
искажённых spam-сообщений (`free→fr33`, `win→w1n`, `claim→cl4im`). Это диагностический
набор, а не реалистичная оценка адаптивной атаки.

## Анализ ошибок

`test_predictions.csv` сохраняет текст, вероятность и ответ. Проверять следует FP с
обычными словами о призах, короткие FN, код-свитчинг, номера и намеренные искажения.

## Запуск

```bash
make install
make train
make evaluate
make predict
make test
```

Прямая проверка: `sms-spam-predict --artifact artifacts/model.joblib --message "..."`.
Пакетный режим принимает `--input messages.csv --output scored.csv`.

## Ограничения модели

Порог зависит от prevalence и цены ошибок. Высокая precision на старом корпусе не
гарантируется на новом трафике; требуется мониторинг, ручной review и регулярная разметка.

## Дальнейшие улучшения

Добавить временной holdout, языковые срезы, sender-признаки с privacy review, bootstrap
интервалы и мониторинг precision среди проверенных сообщений.
## Статус проекта

Word/character TF-IDF, precision-oriented threshold и synthetic smoke-проверка готовы.
Итоговые метрики на зафиксированной версии UCI SMS Spam Collection ещё не заявлены.
